# ADR：生产级能力补齐的技术决策

## 状态
已实现（2026-10）

## 背景
平台已经具备“告警进入 -> AI 推理 -> 修复 -> 验证 -> 报告”的主闭环，
但要作为生产级 AIOps 平台还需补齐：知识可维护、效果可量化、成本可观测、
安全可审计、故障根因可追溯、工具可演练与混沌可验证。

## 决策

### 1. RAG 知识库闭环使用“元数据 + Chroma 增量”而非重装数据库
- 新增 `knowledge_meta.json` 记录文档版本、质量分、内容 hash、审计时间线。
- 同一 source 内容 hash 不变 => 去重跳过；变化 => 删除旧 chunk 后 upsert。
- 版本回滚只切“当前生效版本”，不重复做 embedding，避免回滚成本高。
- 原因：现有 Chroma 已经是唯一向量存储，不引入额外带版本能力的搜索服务。

### 2. 分层评估先把“可作为基准的启发式”交付，LLM-judge 做成可选
- 启发式：token 重叠、Jaccard、断言级支持度。
- LLM-judge：配置 `REFLECTION_*` 后可选开启，失败回退启发式。
- 原因：不依赖外部 judge 也能在离线环境下跑回归；LLM-as-judge 只做校准增强。

### 3. LLM 成本统计独立于 LangFuse
- LangFuse 用于可观测 trace，`cost_tracker` 用于平台内实时成本、预算、缓存、路由。
- 两者职责不重叠，互不依赖。
- 价格表是估算值，生产可改为按供应商计费 API 同步。

### 4. 安全审计用 MySQL 持久化，写失败不阻断业务
- 新增 `audit_logs` 简单宽表，覆盖登录/告警/工具/审批/RAG/混沌。
- 所有审计调用都 try/catch，不因审计服务故障影响主链路。
- 操作回放记录为 `REPLAY` 分类，避免把人工演练混进真实操作统计。

### 5. 新增修复工具全部走既有工具注册、白名单、审批、审计
- 不扩 `generic_command` 权限。
- 高危工具加入 `agent-exposed` 与否由配置文件控制，默认保守。
- 工具页可手工执行，便于演练；AI 调用仍需经过白名单和流程约束。

### 6. 单集群 + namespace 作为环境隔离方案
- 不再维护多套 kind。
- 所有 K8s 查询与操作均绑定当前 namespace，切换成本降低。
- 多环境隔离靠 namespace 命名与配置项，而不是重复集群资源。

## 影响
- 新增接口与页面：知识库管理 API、RAG 分层评估 API、安全审计、根因图谱。
- 新增 Java 实体 `audit_logs`，JPA 自动建表，无需手工迁移。
- Python 新增 JSON/JSONL 管理文件，放在 `VECTOR_STORE_DIR`，不影响主链路。
- 文档同步更新 README 与 docs/rag-advanced.md、docs/security-audit-tools.md。

## 结论
在“不新增外部依赖”约束下，把知识管理、效果评估、成本、审计、故障图和演练能力
补成了可运行的闭环；剩余生产化工作主要是真实验证计费价格、强化 prompt 注入检测
以及把混沌测试接入 LangGraph 真实状态图。
